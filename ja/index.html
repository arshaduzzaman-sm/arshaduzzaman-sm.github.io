01 — 自己紹介

良いテストとは、バグを見つけることだけではありません。チーム全員が自信を持ってリリースできるようにすることです。

東京でSQAエンジニアとして、IoTを活用したビルオートメーション・エネルギーマネジメントシステムのテストをエンドツーエンドで担当しています。現場のデバイスやファームウェアから、Linuxエッジゲートウェイ、クラウドプラットフォーム、Webアプリ、REST APIまでが対象です。

主な業務はシステムテスト、回帰テスト、負荷テストです。不具合が起きたときは、ログやネットワークを調べ、何が起きたのか、どうすれば再現できるのかを開発者に明確に示します。テストを効率化するPythonツールも作成しており、自作のMQTTトラフィック生成スクリプトは社内の標準負荷テストに採用されています。

テストにはAIも活用しています。ClaudeやGitHub Copilotを使って、要件からテストケースの下書きを作成したり、テストスクリプトを効率よく書いたり、失敗したテストの原因を調べたりしています。AIが出した結果は必ず自分で確認してからテスト計画に反映します。SmartIoTプロジェクトでは、これを行う小さなツールをClaude APIで作りました。

SQAの前は、オペレーティングエンジニアとして全自動のセンサー生産ラインの稼働を支えていました。そこで「当たり前に動くシステム」に多くの人が頼っていることを実感しました。現在は英語と日本語を毎日使いながら、チームをつなぎ、品質を前に進める役割にやりがいを感じています。

02 — テストの進め方

テストの進め方

業務のスマートビル用ゲートウェイでも、個人で作ったプラットフォームでも、同じ4つのステップで品質を確かめます。

  1. 01

    計画する

    まず製品とリスクを理解します。要件を読み込み、起こりうる問題を洗い出し、正常系・異常系・境界値をカバーするテストケースを作成します。

    • Test case design
    • Requirements
    • Jira
    • Claude API

    SmartIoT：11件の要件すべてを、それを証明するテストと紐付け

  2. 02

    自動化する

    2回以上実行するテストはスクリプト化します。APIチェック、ブラウザテスト、MQTTトラフィック生成をCIで実行し、すべての変更に同じ確認を行います。

    • Python
    • pytest
    • Playwright
    • Postman
    • GitHub Actions
    • GitHub Copilot

    7層・816件の自動テスト · 自作のMQTT負荷スクリプトは社内の標準負荷テストに採用

  3. 03

    あえて壊す

    実際のユーザーやネットワークは想定どおりには動きません。高負荷をかけ、アップデート中に接続を切り、サービスを停止して、どう壊れ、どう復旧するかを確認します。

    • Load testing
    • k6
    • Failure injection
    • FOTA

    負荷テストでスループットを毎秒124→303リクエストに改善（エラー率0%）

  4. 04

    報告して証明する

    良いバグ報告は修正を簡単にします。ログやネットワークを調べて原因と再現手順を明確に示し、回帰テストで再発を防ぎます。

    • Log analysis
    • Root cause
    • Regression

    SmartIoTで41件の不具合を発見・修正し、すべて回帰テストで再発を防止
